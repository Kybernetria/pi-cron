# pi-cron

Daemon-owned persistent scheduling for Pi. A job executes exactly one of:

- **chat** — a normal prompt in a new in-memory Pi SDK session with an explicit working directory;
- **protocol** — one exact `node.provide` invocation with schema-validated JSON input and an ephemeral protocol session.

The Pi extension contains no timers or storage. Every extension instance delegates to the single Rust daemon over a private Unix socket; TypeScript is limited to the Pi UI/client and short-lived action runner.

## Requirements

- Linux/Unix
- Rust toolchain for building the daemon
- Node.js 22.19 or newer for short-lived Pi runner processes
- Pi and pi-protocol

## Install and run

This directory is already a Pi package (`pi.extensions` points to `extension.ts`). Install dependencies and build the production daemon before reloading Pi:

```bash
npm install
npm run build:daemon
```

The first `/cron` command or `pi_cron.*` invocation then starts that binary on demand. For a durable login service, also run:

```bash
npm run install:daemon-service
```

Manual foreground operation:

```bash
npm run daemon
```

Default locations:

- database: `${XDG_STATE_HOME:-~/.local/state}/pi-cron/jobs.sqlite`
- socket/lock: `$XDG_RUNTIME_DIR/pi-cron/` (or the state directory's `run/` subdirectory without XDG runtime)

Override them with `PI_CRON_DB`, `PI_CRON_SOCKET`, `PI_CRON_STATE_DIR`, or `PI_CRON_RUNTIME_DIR`. Set `PI_CRON_DAEMON_BIN` to an alternate release binary.

Node starts only for protocol validation or action execution. IPC and frozen compatibility details are in [`docs/ipc-v1.md`](docs/ipc-v1.md) and [`docs/compatibility.md`](docs/compatibility.md).

## Commands

Run `/cron` with no arguments to open the guided manager. It provides create, browse, view, edit, run-now, enable/disable, and confirmed delete flows using Pi's standard dialogs.

Direct commands remain available:

```text
/cron list
/cron add
/cron edit [id]
/cron delete [id]
/cron run [id]
/cron enable <id>
/cron disable <id>
/cron help
```

Add guides you through the name, standard five-field cron schedule, and action. New jobs automatically capture the device's current IANA timezone; edit allows changing it later. Chat actions ask for a prompt and absolute working directory. That canonical directory is both the runner process cwd and the Pi SDK cwd.

Protocol actions ask for:

```json
{
  "type": "protocol",
  "target": "pi_ng.send",
  "input": { "message": "Scheduled message" }
}
```

## Protocol API

The `pi_cron` node registers:

- `pi_cron.add` — `{ job }`; id is optional and generated by the daemon
- `pi_cron.edit` — `{ job }`; complete replacement including id
- `pi_cron.delete` — `{ id }`
- `pi_cron.list` — `{}`
- `pi_cron.get` — `{ id }` (also returns bounded occurrence history)
- `pi_cron.enable` / `pi_cron.disable` — `{ id }`
- `pi_cron.run_now` — `{ id }`

Protocol discovery and execution use the daemon user's canonical `$HOME`; path-sensitive targets must carry their own explicit path in `input`. Both action types load user/global Pi resources only: unattended jobs do not trust or execute cwd-local settings, extensions, skills, prompts, or context files. Direct `pi_cron.*` targets are rejected to prevent recursive scheduling.

All handlers are socket clients. The daemon validates complete jobs before SQLite mutation, including cron parsing, IANA timezone and next-occurrence calculation, real chat cwd, target existence, JSON serializability, and the selected provide's JSON Schema.

## Execution guarantees

- A single-instance lock is acquired before SQLite is opened.
- SQLite `BEGIN IMMEDIATE` plus unique `(job_id, scheduled_at)` claims prevents duplicate occurrences.
- Due occurrences are claimed promptly and one execution gate serializes their external effects.
- Claims are persisted before effects and always terminalized as `completed` or `skipped`.
- Interrupted claims become `skipped` on restart.
- No action is retried and missed schedules are not caught up.
- One timer tracks the nearest indexed `next_at`; every mutation and wake-up recalculates it.
- Results are capped at 40,000 characters and history at 100 occurrences per job.
- The socket and lock are user-private (`0600`, containing directory `0700`).

Protocol output summaries include trace/span terminal events. Every chat/bootstrap/protocol session is disposed before its short-lived runner exits.

## Test

```bash
npm test
```

Tests cover standard weekday and day-of-month/day-of-week cron behavior, timezone/DST handling, v1 database compatibility, history bounds, malformed and concurrent IPC, runner failures/timeouts/limits, private file modes, and daemon single-instance locking.

## MVP exclusions

No retries, catch-up, parallel jobs, pipelines, callbacks, shell actions, environment interpolation, natural-language schedules, persistent conversations, remote management, or web UI.
